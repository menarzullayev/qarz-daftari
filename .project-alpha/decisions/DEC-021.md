# Decision Record

- Decision ID: DEC-021
- Stage: 08-technical-spec
- Title: Database roles and cross-tenant functions
- Decision: The migration creates role qd_app without login or password, which are set at deploy. Two SECURITY DEFINER functions were added beyond the approved schema: mark_recipient_unreachable(bigint) for the outbox dispatcher and accept_staff_invitation(bytea, uuid) for joining a shop. Their owner, the migration role, must be able to bypass row-level security.
- Context: Decided by the orchestrating agent during the autonomous build under DEC-020; implemented and awaiting the founder's review. The approved schema.sql sets a password literal for qd_app and names cross-tenant functions only as a list in the specification.
- Chosen option: Role created NOLOGIN; narrow SECURITY DEFINER functions for the two cross-tenant actions
- Rationale: A password literal must not live in the repository. The application role sees no rows without a tenant, so the two actions that are inherently cross-tenant need a narrow function; giving the application role broader access would defeat the isolation required by ADR-016.
- Impact: Medium
- Reversibility: High
- Risk: MEDIUM
- Evidence: EVID-036, EVID-038
- Approval required: yes
- Approval status: pending
