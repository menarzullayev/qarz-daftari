# Decision Record

- Decision ID: DEC-023
- Stage: 04-prd
- Title: Shop creation and staff details
- Decision: Staff invitations expire after 7 days. A removed member who is invited again gets the same membership row back with the newly invited role. A repeated invite request returns the invitation identifier but not the token again. A new shop's identifier is derived from the caller and the idempotency key. PATCH on a shop changes only name, language and default promise days. No limit yet on shops per person.
- Context: Decided by the orchestrating agent during the autonomous build under DEC-020; implemented and awaiting the founder's review. The PRD and domain model do not state an invitation lifetime; the domain model calls a removed membership final while the schema allows one membership per user per shop.
- Chosen option: 7-day invitations; reactivate the same membership row; token handed out once
- Rationale: Keeping the membership row keeps a person's earlier entries attributed to them (REQ-034); never storing the token follows the specification's rule that only hashes are stored.
- Impact: Medium
- Reversibility: High
- Risk: MEDIUM
- Evidence: EVID-034
