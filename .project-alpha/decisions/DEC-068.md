# Decision Record

- Decision ID: DEC-068
- Stage: 04-prd
- Title: Three database roles; sign out everywhere
- Decision: The API, the administrators' side and the worker each connect to the database as a role of their own: qd_app, qd_admin and qd_worker, the two new ones created without a login like qd_app (migration 0031). Each is granted only what its code runs. One function, forget_user_if_unused, is held by both qd_app and qd_worker, because both complete a customer's removal. The ordinary role learns whom to tell that a receipt waits through a new function, admin_notice_recipients, instead of reading admin_account, and of the outbox it reads five columns and not the recipient or the text. The administrators' side stays in the API's process, which therefore holds two connections; an administrator's decision in the chat goes through the administrators' connection. Neither the API nor the worker falls back to the ordinary connection when its own is missing: they refuse to start. The migration is not compatible with the release before it, against the rule that such a change is split across two releases, because nothing is deployed yet; the way back is one GRANT of the two new roles to qd_app. Sign out everywhere ends every session of the person, the current one included; like sign-out it answers 204 and takes no Idempotency-Key; it is offered, with a confirmation, on the overview of the Mini App and of the shop panel and under a customer's accounts. The administrators' panel was left as it is, because closing an admin session already ends every admin session of that administrator. No daily cap on new shops was added (DEC-065)
- Context: Decided by an agent during the autonomous build under DEC-020; implemented and awaiting the founder's review
- Chosen option: Choices as listed in pull request 68
- Rationale: The security review named the gaps (findings 9 and 11); the documents name one application role and say nothing about ending a person's sessions on other devices
