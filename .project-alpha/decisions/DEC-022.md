# Decision Record

- Decision ID: DEC-022
- Stage: 08-technical-spec
- Title: Sessions and sign-in details
- Decision: A user_session table was added (hashes only). Signed Telegram data is accepted for at most one hour in both formats. A failed CSRF check answers 401 like a missing session. PATCH /api/v1/me needs no idempotency key. Bearer tokens are accepted only for Mini App sessions and cookies only for web sessions.
- Context: Decided by the orchestrating agent during the autonomous build under DEC-020; implemented and awaiting the founder's review. The approved schema mentions sessions but defines no table; the specification gives one hour for Mini App data and no figure for Login Widget data.
- Chosen option: Server-side hashed sessions; one-hour signature age; kinds not interchangeable
- Rationale: Follows ADR-017 and the security section of the specification; refusing a web session token as a bearer token closes a way around the CSRF check.
- Impact: Medium
- Reversibility: High
- Risk: MEDIUM
- Evidence: EVID-039
